[KRITIS-01] Dead code memanggil model "Validasi" yang tidak ada

            tapi bom waktu jika suatu saat dipakai)
Lokasi    :
  - app/Services/KaderService.php (baris 8 dan 34: Validasi::create())
  - app/Services/PuskesmasService.php (baris 7, 21, 27)
  - app/Services/Puskesmas/PuskesmasService.php (baris 8, 42, 86, 93, 285-286)
Masalah   : Ketiga file ini meng-import App\Models\Validasi, padahal model
            Validasi dan tabel validasis TIDAK ADA di database/migrations.
Dampak    : Jika service ini dipakai, penyimpanan pengukuran akan FATAL ERROR
            setelah Pengukuran::create() (di dalam DB::transaction -> rollback).
Catatan   : Jalur UTAMA simpan pengukuran sekarang lewat
            app/Http/Controllers/Kader/KaderController.php baris 695-710
            (langsung Pengukuran::create dengan status_validasi 'pending')
            dan SUDAH BENAR - tidak menyentuh model Validasi.
Tindakan  :
  [ ] Hapus app/Services/KaderService.php
  [ ] Hapus app/Services/PuskesmasService.php
  [ ] Hapus folder app/Services/Puskesmas/ (berisi PuskesmasService.php versi lama)
  [ ] Hapus folder app/Services/PortalIbu/ (versi lama, lihat KRITIS-03)
  [ ] Hapus app/Services/PortalIbuService.php (versi lama, tidak sinkron
      dengan controller aktif)
  [ ] Verifikasi: grep -rn "Validasi" app/ hasilnya harus kosong
      (kecuali nama variabel $statusValidasi yang aman)

[KRITIS-02] Signed URL dibuat tapi tidak pernah dikirim ke Ibu
----------------------------------------------------------------
Status    : Masih terjadi persis seperti di audit
Lokasi    : app/Http/Controllers/Puskesmas/PuskesmasController.php
            baris 351 ($signedUrl) sampai 359 (return redirect)
Masalah   : Saat approve(), URL::temporarySignedRoute('portal-ibu.home',
            now()->addDays(7), ['balita' => ...]) dibuat ke variabel
            $signedUrl, tetapi variabel itu TIDAK PERNAH dipakai:
            tidak dikirim via WhatsApp, tidak disimpan ke database,
            tidak ditampilkan ke user. User hanya menerima flash message
            generik "Data balita berhasil disetujui".
Bug tambahan di fungsi yang sama:
            baris 354-357 menghitung $stats tapi juga tidak dipakai
            (dead code kedua).
Dampak    : Ibu TIDAK PERNAH menerima link portal setelah data disetujui.
            Alur Kader -> Puskesmas -> Ibu PUTUS di langkah terakhir.
Tindakan  :
  [ ] Short-term (untuk demo hackathon): tampilkan signed URL di flash
      message / halaman detail antrean setelah approve, mis:
      return redirect()->route('puskesmas.validasi')->with([
          'success' => '...',
          'portal_link' => $signedUrl,
      ]);
      Lalu render tombol "Salin Link" + tombol WhatsApp di view:
      https://wa.me/{no_hp_whatsapp}?text={urlencode($signedUrl)}
      (nomor diambil dari balita.orangTua.no_hp_whatsapp)
  [ ] Hapus atau gunakan variabel $stats (baris 354-357)
  [ ] Long-term: buat service WA gateway + tabel log pengiriman
      (lihat TINGGI-02)

[KRITIS-04] IDOR: Portal Ibu membuka data balita mana pun hanya dengan
            mengubah angka ID di URL
----------------------------------------------------------------
Status    : Masih terjadi - BELUM DIPERBAIKI
Lokasi    : app/Http/Controllers/PortalIbu/PortalIbuController.php
            baris 24-33 (fungsi getActiveBalita)
Masalah   : getActiveBalita() hanya melakukan:
              Balita::with(...)->find(request('balita'))
            Tidak ada pengecekan apakah pemilik signed URL berhak atas
            balita tersebut.
Skenario serangan:
            Ibu A menerima signed URL untuk balita miliknya:
            /portal-ibu/dashboard?balita=5&signature=...
            Ubah jadi ?balita=7 (tetap dengan signature yang sama) ->
            data balita 7 (milik orang lain) tampil lengkap: nama anak,
            riwayat pengukuran, grafik, jadwal posyandu.
            Ini melanggar privasi kesehatan anak (data medis).
Dampak    : Data kesehatan balita bocor antar keluarga. Fatal untuk
            kredibilitas aplikasi kesehatan di mata juri/user.
Tindakan  (pilih salah satu strategi, JANGAN dicampur):
  Opsi A (disarankan, paling cepat):
    [ ] Di approve() PuskesmasController baris 351, tambahkan parameter
        orang_tua_id ke signature:
          URL::temporarySignedRoute('portal-ibu.home', now()->addDays(7),
            ['balita' => $id, 'orang_tua' => $pengukuran->balita->orang_tua_id])
    [ ] Di getActiveBalita():
          $orangTuaId = request('orang_tua');
          return Balita::with([...])
              ->where('id', $balitaId)
              ->where('orang_tua_id', $orangTuaId)
              ->first();
        (jika orang_tua_id tidak cocok -> null -> halaman empty state)
    [ ] Pastikan SEMUA link internal portal meneruskan parameter
        orang_tua (cek route names portal-ibu.posyandu/growth/nutrition
        di view blade)
  Opsi B (lebih rapi tapi lebih kerja):
    [ ] Tambah kolom access_token unik di tabel orang_tuas (migration baru)
    [ ] Signed URL memuat token, controller cocokkan token -> orang_tua_id
        -> scope semua query balita
  [ ] Buat test: buka URL dengan balita_id milik orang lain HARUS empty

[TINGGI-01] Navigasi internal Portal Ibu rawan menghasilkan URL invalid
----------------------------------------------------------------
Lokasi    : routes/web.php baris 151-157 (grup middleware 'signed'),
            semua route portal-ibu.* memakai middleware signed.
Masalah   : Signature hanya sah untuk exact URL. Link di dalam halaman
            portal (mis. menu ke /grafik?balita=X) harus punya signature
            sendiri; kalau view membuat link tanpa signature ->
            error 403 Invalid signature saat diklik.
Tindakan  :
  [ ] Audit semua <a href> / redirect di views/portal-ibu/**
      - pastikan setiap internal link dibuat dengan URL::temporarySignedRoute
        (bukan route() biasa) ATAU ganti strategi: signed HANYA di route
        dashboard (pintu masuk), setelah lolos -> simpan balita_id +
        orang_tua_id di session, route lanjutan cukup middleware web.
      - Strategi session lebih sederhana untuk demo.

            no_hp_whatsapp tersimpan di orang_tuas (sudah unique, bagus)

Tindakan  :
  [ ] Minimal untuk demo: link wa.me (lihat KRITIS-02 short-term)
  [ ] Jika sempat: buat App\Services\WhatsAppService dengan driver
